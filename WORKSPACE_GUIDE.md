# Prince of Persia: SnF PC Port - Workspace Guide

This document is the definitive guide to workspace organization, directory layout, asset provenance, build pipeline, and developer hygiene for contributors working on this codebase.

---

## High-Level Workspace Architecture

The workspace is partitioned into **three segregated categories**:

```
SnF PC Port/
├── 1. Standalone Game Runtime      [game/]
├── 2. Reference & Context Assets   [ref_assets/, screenshots/]
└── 3. Source Code & Build Pipeline [src/, third_party/, tools/, build_app/, scratch/, CMakeLists.txt]
```

---

## Category Breakdown

### 1. Standalone Game Runtime (`game/`)
**Purpose**: Contains **only** the self-contained files needed to configure, run, and play the game.

The runtime folder is designed around a **clean, pristine STK-only architecture**. All 4,617 models, textures, scenes, audio tracks, and XML manifests are streamed directly from the encrypted `S3DMain.stk` archive via our guest Virtual File System (VFS) bridge without requiring loose asset folders on disk.

| Item | Type | Description |
| :--- | :--- | :--- |
| `game/PoPSnF_Launcher.exe` | Binary | Nostalgic PoP 2008-styled Launcher, Configurator & APK Extractor. |
| `game/PoPSnF_Reignited.exe` | Binary | Compiled native Windows x64 game engine executable. |
| `game/SDL2.dll` | Library | 64-bit SDL2 runtime library. |
| `game/OpenAL32.dll` | Library | 64-bit OpenAL Soft runtime library. |
| `game/libS3DClient.so` | Shared Library | Original ARMv7 engine binary extracted from mobile release. |
| `game/S3DMain.stk` | Game Archive | Master encrypted ShiVa3D asset package (extracted from `assets/S3DMain.smf`). |
| `game/app_splash.png` | Startup UI | Original Android activity splash, displayed by the native host while the guest engine initializes. |
| `game/config.ini` | Configuration | User settings: display resolution, fullscreen, VSync, MSAA, AF, and key/pad bindings. |
| `game/Saves/` | Data Directory | Persistent player save data (`POP2SaveData.sts`). |
| `game/logs/` | Log Directory | Timestamped session logs (`pop_pc_<timestamp>.log`). |
| `game/Cache/` | Cache Directory | Runtime shader and texture cache generated by the engine. |

> [!NOTE]
> **No Loose Game-Asset Folders Required**: Gameplay content runs from `S3DMain.stk` and `libS3DClient.so`; `app_splash.png` is the separate Android activity resource used only during host startup. Folders like `Resources/`, `Models/`, `Scenes/`, and `Games/` are **not** needed for normal gameplay. If loose asset directories are present, the VFS will prioritize them as custom mod overrides before searching inside `S3DMain.stk`.

> [!IMPORTANT]
> **Logging & Isolation**:
> - All session logs live strictly in `game/pop_pc.log` and `game/logs/`, never at the repository root.
> - Both executables lock their working directory to their own folder on startup (`SetCurrentDirectoryA`), preventing path pollution or accidental reads from outside directories.

## How to Build the Game

Set the portable toolchains in your PowerShell environment before building:

```powershell
$env:PATH = "$PWD\tools\w64devkit\bin;$PWD\tools\cmake\bin;" + $env:PATH
```

### Compiling
Configure and build both targets (`PoPSnF_Reignited` and `PoPSnF_Launcher`):
```powershell
cmake -B build_app -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build_app
```
CMake compiles modified files in `src/`, links against prebuilt dependencies, and automatically deploys `PoPSnF_Reignited.exe`, `PoPSnF_Launcher.exe`, `SDL2.dll`, and `OpenAL32.dll` to `game/`.

## How to Run and Configure the Game

### Method 1: The Launcher & Configurator (Recommended)
Launch `PoPSnF_Launcher.exe` directly from `game/`:
```powershell
.\game\PoPSnF_Launcher.exe
```
From the Launcher, you can:
- **Extract Assets**: If game assets are missing, click **"Extract Game Assets"**, select your original `.apk` file, and the launcher will unpack `libS3DClient.so`, `S3DMain.stk`, and `app_splash.png` in under 1 second.
- **Configure Graphics**: Select display resolutions (native 16:9 widescreen up to 4K UHD), toggle borderless Fullscreen, VSync (60 FPS lock), MSAA Anti-Aliasing (up to 8x), and Anisotropic Filtering (up to 16x).
- **Configure Controls**: Remap Primary Keyboard/Mouse, Secondary Keyboard/Mouse, and Gamepad buttons with:
  - **Conflict Swapping**: Automatically swaps keys when rebinding conflicting actions.
  - **Mouse Scroll Wheel**: Map `Wheel Up`, `Wheel Down`, `Wheel Left`, or `Wheel Right` to any action.
  - **Dolphin-Style Escape Binding**: Hold `Escape` for 750ms or double-tap to bind Escape; quick tap cancels.
  - **Undo / Redo History**: Undo (`Ctrl+Z`) and Redo (`Ctrl+Y`) for remapping changes or accidental default resets.
- **Launch the Game**: Launches `PoPSnF_Reignited.exe` with your configured settings.

### Method 2: Direct Game Play (CLI)
Launch `PoPSnF_Reignited.exe` directly:
```powershell
.\game\PoPSnF_Reignited.exe
```

### Method 3: Headless Automated Regression Testing
Pass diagnostic arguments to verify menus or gameplay without manual input:

| Command | Action |
| :--- | :--- |
| `.\game\PoPSnF_Reignited.exe --headless --frames 120` | Headless sanity check (120 frames). |
| `.\game\PoPSnF_Reignited.exe --headless --menu coins --frames 250` | Enters Coin Store and captures frames 160-250. |
| `.\game\PoPSnF_Reignited.exe --headless --menu world_map --frames 250` | Enters World Map menu and captures screenshots. |
| `.\game\PoPSnF_Reignited.exe --headless --menu new_game --frames 1750` | Plays intro cutscenes and enters Level 1 courtyard. |
| `.\game\PoPSnF_Reignited.exe --headless --action level1_play --frames 1200` | Enters Level 1 and verifies gameplay controls. |

### Method 4: Launcher Command-Line Interface
| Command | Action |
| :--- | :--- |
| `.\game\PoPSnF_Launcher.exe --extract <path-to-apk>` | Headlessly extracts game assets into current folder. |
| `.\game\PoPSnF_Launcher.exe --screenshot <file.bmp>` | Saves a screenshot of the main launcher screen. |
| `.\game\PoPSnF_Launcher.exe --settings-screenshot <file.bmp>` | Saves a screenshot of the graphics options tab. |
| `.\game\PoPSnF_Launcher.exe --controls-screenshot <file.bmp>` | Saves a screenshot of the controls options tab. |

## Rules & Hygiene for Contributors and LLM Agents

1. **Maintain Root Directory Cleanliness**:
   - The repository root must never contain loose screenshots, temporary files, `.log` files, or directory dumps.
   - All runtime files, logs, and save data belong in `game/`.
   - All diagnostic screenshots belong in `screenshots/`.
   - Temporary scripts and dumps belong in `scratch/`.
2. **Pristine `game/` Folder Discipline**:
   - Do not populate `game/` with loose `Resources/`, `Models/`, `Scenes/`, or `Games/` trees unless specifically authoring a mod override. The game runs purely from `S3DMain.stk`.
3. **Do Not Modify Reference Folders**:
   - `ref_assets/` is strictly read-only provenance.
4. **Working Directory Isolation**:
   - Always assume the application runs with its working directory set to `game/`. Never rely on relative paths pointing back into `../ref_assets/` or the project root.
5. **Version Tagging**:
   - When introducing bug fixes or major changes, increment `BUILD_NUMBER` and `BUILD_TAG` in `src/build_version.h`.
